# Smart Rental — System Architecture

## Overview

Smart Rental (RentSense) is a **TanStack Start** application with a **Nitro** SSR layer deployed on Cloudflare Module Workers. The frontend is a rich React SPA with an Apple-inspired premium design system.

---

## Stack

| Layer | Technology |
|-------|-----------|
| **Framework** | TanStack Start (TanStack Router + Nitro) |
| **UI** | React 19, Tailwind CSS v4, Radix UI primitives |
| **State** | `useSyncExternalStore` (custom reactive store in `src/data/fleet.ts`) |
| **Map** | Leaflet (GPS telemetry visualization) |
| **Database** | Supabase (PostgreSQL + RLS + Auth) |
| **Email** | Resend (via Supabase Edge Function — server-side only) |
| **Build** | Vite 8 + Rolldown, deployed to Cloudflare |
| **QR Scanning** | jsQR (in-browser camera QR decode) |

## Alert System

Alerts are generated by a **single unified function**: `buildAlerts(assets)` in `fleet.ts`.

This is the **only** source of alert counts — used by:
- The status bar in `Shell.tsx` (via `summary()` which calls `buildAlerts()`)
- The Alert Command Center (`/alerts`)
- The Notification Center popover

**Alert types** (in priority order):
1. `Overdue` — past return date, still active → severity: `critical`
2. `Due Soon` — within 5 days of return → severity: `warning`
3. `Unassigned` — no site or operator → severity: `warning`
4. `Low Utilization` — below 25% → severity: `warning`
5. `Maintenance` — high duty cycle anomaly → severity: `info`

## Email Notification Architecture

```
Browser (React)                Supabase Edge Function         Resend API
       │                              │                           │
       │  notifyAlertEmail()          │                           │
       │ ──────────────────────────→ │                           │
       │  POST /functions/v1/         │  RESEND_API_KEY           │
       │  send-alert-email            │  (Supabase Secret)        │
       │  Authorization: Bearer       │  ──────────────────────→ │
       │  <SUPABASE_ANON_KEY>         │                           │
       │                              │ ←── email ID ─────────── │
       │ ←── { success, id } ─────── │                           │
```

**Security**: `RESEND_API_KEY` is stored as a Supabase Secret. It never appears in the browser bundle. Only the `VITE_SUPABASE_ANON_KEY` (safe to expose) is used client-side to authenticate the Edge Function call.

## Financial Architecture

The deposit / revenue separation is enforced at every layer:

```
NewRentalModal.tsx
  ├── monthlyRate (editable number input)      → rental REVENUE
  └── securityDeposit (editable number input)  → escrow LIABILITY

createRentalContract() in fleet.ts
  ├── accepts: monthlyRentalRate (explicit, NOT defaulted)
  └── accepts: securityDepositAmount (explicit, NOT combined with revenue)

RentalContract type
  ├── monthly_rental_rate   ← P&L revenue column
  └── security_deposit_amount  ← Balance sheet liability column
```

## Security Notes

- `.env`, `.env.local` are in `.gitignore` — never commit real secrets
- `RESEND_API_KEY` MUST be a server-side secret only (Supabase Secret, not `VITE_` prefix)
- `VITE_SUPABASE_ANON_KEY` is safe to expose (it's public per Supabase design, protected by RLS)
- All database access goes through Supabase RLS policies
